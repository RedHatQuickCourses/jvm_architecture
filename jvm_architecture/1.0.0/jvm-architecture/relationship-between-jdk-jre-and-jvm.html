Relationship between JDK, JRE, and JVM

Relationship between JDK, JRE, and JVM

Java’s ecosystem comprises several fundamental components that work together to enable the development and execution of Java applications. Understanding the hierarchical relationship and distinct roles of the Java Development Kit (JDK), Java Runtime Environment (JRE), and Java Virtual Machine (JVM) is crucial for any Java developer or administrator.

Introduction to JDK, JRE, and JVM

At its core, Java’s "write once, run anywhere" philosophy is achieved through these three components. They form a layered architecture, with each layer building upon the capabilities of the one beneath it, providing a complete environment for Java programs.

  • JVM (Java Virtual Machine): The innermost layer and the actual runtime engine. It’s responsible for executing Java bytecode, providing the runtime environment for a Java program to execute.

  • JRE (Java Runtime Environment): This layer contains the JVM along with the core Java class libraries and supporting files. It provides everything necessary to run a compiled Java application.

  • JDK (Java Development Kit): The outermost and most comprehensive layer. It includes the JRE, plus additional development tools that allow developers to develop, compile, and debug Java applications.

JVM: The Java Virtual Machine

The JVM is an abstract computing machine that enables a computer to run Java programs. When Java source code (.java files) is compiled, it’s converted into platform-independent bytecode (.class files). The JVM then takes this bytecode and executes it on the underlying operating system and hardware, translating the bytecode into machine-specific instructions. This translation process is what allows Java to achieve its "write once, run anywhere" capability.

Key responsibilities and characteristics of the JVM:

  • Bytecode Execution: Loads, verifies, and executes Java bytecode.

  • Runtime Environment Provider: Creates a dedicated runtime environment for each Java application instance, managing resources required for its execution.

  • Memory Management: Allocates and manages memory for various parts of a Java application, including the heap (for objects), method area (for class structures), stack (for method execution), and native method stack.

  • Garbage Collection: Automatically identifies and reclaims memory occupied by objects that are no longer referenced by the running application, preventing memory leaks.

  • Just-In-Time (JIT) Compiler: Modern JVMs include a JIT compiler that can compile frequently executed bytecode sequences into native machine code at runtime, significantly improving performance.

  • Security Manager: Enforces security policies to control what resources a Java application can access.

JRE: The Java Runtime Environment

The JRE is a collection of components that provide the necessary environment to run Java applications. It is specifically designed for end-users or deployment environments where only the execution of Java programs is required, not their development.

The JRE fundamentally comprises:

  • Java Virtual Machine (JVM): As detailed above, this is the core engine for bytecode execution.

  • Java Class Libraries: A vast set of pre-written code (organized into packages like java.lang, java.util, java.io, java.net, etc.). These libraries provide common functionalities such as input/output operations, networking, data structures, UI toolkits, and more, which Java applications can leverage.

  • Supporting Files: Other configuration files and resources crucial for the smooth operation of the Java platform.

When you install a JRE, you get everything required to execute a compiled Java application. However, you cannot compile new Java source code with a JRE alone, as it lacks the necessary development tools like the Java compiler (javac).

JDK: The Java Development Kit

The JDK is the comprehensive Java environment for developing, compiling, and running Java applications. If you are a Java developer, the JDK is indispensable, as it provides all the tools needed to write, compile, debug, and package Java code. The JDK encapsulates the JRE, along with additional development utilities.

The JDK comprises:

  • Java Runtime Environment (JRE): This includes the JVM and the core Java class libraries, enabling the execution of Java applications.

  • Development Tools: These are command-line utilities crucial for the Java development workflow:

  • javac: The Java compiler, which translates Java source code (.java files) into platform-independent Java bytecode (.class files).

  • java: The Java application launcher, which starts a JVM and executes a compiled Java application (.class files or .jar files).

  • jar: The Java archive tool, used to package related classes, resources, and metadata into a single JAR (Java Archive) file.

  • javadoc: The Java documentation tool, which generates API documentation in HTML format from special comments within Java source code.

  • jdb: The Java Debugger, a command-line utility for debugging Java applications.

  • jconsole, jvisualvm: Monitoring and profiling tools that provide graphical interfaces to monitor and manage Java applications and JVMs.

  • Other utility tools for signing JARs, native-to-Java interface headers, etc.

Vendors and Variations of JDK

While the core functionality and adherence to the Java SE specification remain consistent, there are multiple implementations of the JDK provided by various vendors:

  • Oracle JDK: The commercial and historically dominant implementation provided by Oracle.

  • OpenJDK: The open-source reference implementation of the Java Platform, Standard Edition (Java SE). Many organizations, including Red Hat, contribute significantly to OpenJDK and provide their own distributions (e.g., Red Hat build of OpenJDK).

  • IBM JDK: An implementation provided by IBM, often optimized for IBM’s own server platforms and middleware products.

The choice of JDK vendor often depends on licensing considerations, specific performance optimizations, and integration with other vendor-specific software. Regardless of the vendor, the fundamental architecture and core functionalities for developing and running Java applications are preserved according to the Java SE specification.

When to Use Which: Practical Implications

Understanding when to use JDK, JRE, or how the JVM fits in is key to setting up your Java environment correctly:

  • For Java Developers: If you are involved in writing, compiling, debugging, or packaging Java applications, you must install the JDK. It provides all the necessary tools and the runtime environment.

  • For Running Java Applications: If you only need to execute pre-compiled Java applications (e.g., on a production server, a client machine, or for testing purposes), a JRE is technically sufficient. It provides the JVM and core libraries without the development overhead.

  • JVM’s Role: The JVM is an integral component within both the JRE and JDK. You don’t install the JVM as a standalone entity; it comes bundled with either a JRE or a JDK.

In practical scenarios, particularly for servers and development machines, installing the JDK is a common practice. This is because the JDK includes the JRE and provides valuable diagnostic and management tools (jcmd, jstack, jmap, jstat, jconsole) that are often needed for monitoring and troubleshooting running Java applications, even in a production environment. For modern JDKs (Java 9+), the JRE components are often deeply integrated within the JDK installation, making the distinction between a separate JRE installation less common.

Hands-on Lab: Exploring the JDK Installation

This lab will guide you through exploring a typical JDK installation directory. By physically navigating the file system, you will visually identify the JRE components and development tools, solidifying your understanding of their relationship within the overall JDK structure.

Objective

  • To locate and identify the core components of the JDK, JRE (or its integrated parts), and key development tools within a local Java installation.

  • To understand the directory structure that reflects the hierarchical relationship between these components.

Prerequisites

  • A machine with a Java Development Kit (JDK) already installed. Any standard JDK installation (e.g., OpenJDK, Oracle JDK 8+) will suffice. If you haven’t installed one, please refer to the "Installing JDK using Subscription Manager" lab later in this module.

  • Basic command-line navigation skills (e.g., cd, ls/dir).

Step-by-step Instructions

  1. Locate Your JDK Installation Directory:

    • Open a terminal or command prompt.

    • The JDK root directory is typically where JAVA_HOME environment variable points, or where the java executable resides.

    • On Linux/macOS:

    • Check JAVA_HOME: echo $JAVA_HOME

    • If not set, find java executable: which java then ls -l $(which java) to see the symlink to the actual JDK path. Common paths: /usr/lib/jvm/, /opt/java/.

    • On Windows:

    • Check JAVA_HOME: echo %JAVA_HOME%

    • Common paths: C:\Program Files\Java\jdk-VERSION\ or C:\Program Files\AdoptOpenJDK\jdk-VERSION\.

  2. Navigate to the JDK Root Directory:

    • Change your current directory to the identified JDK root.

    • Example (Linux): [,bash] ---- cd /usr/lib/jvm/java-17-openjdk-amd64 ----

    • Example (Windows): [,powershell] ---- cd "C:\Program Files\Java\jdk-17" ----

  3. Explore the bin Directory (Development Tools and Java Launcher):

    • List the contents of the bin subdirectory: [,bash] ---- ls bin/ ----

    • Example (Windows): [,powershell] ---- dir bin\ ----

    • Expected Outcome: You should observe executables such as javac (the Java compiler), java (the Java application launcher), jar (archive tool), javadoc (documentation generator), and potentially jdb, jconsole, etc. The presence of javac is a key indicator that this is a JDK installation.

  4. Identify JRE Components (JVM and Core Libraries):

    • For JDK 8 and older: Look for a separate jre subdirectory within the JDK root. [,bash] ---- ls jre/ ---- If present, this jre directory would contain its own bin (with java but no javac) and lib directories.

    • For JDK 9 and newer (Modular JDKs): The JRE is no longer a separate directory but is integrated into the main JDK structure.

    • The lib directory at the JDK root contains the core runtime libraries (e.g., lib/modules for modular JARs, or lib/rt.jar for older versions before modularity).

    • The bin directory at the JDK root serves for both development and runtime, containing the java launcher and other tools.

    • Expected Outcome: You will find the necessary runtime libraries either in a dedicated jre folder (older JDKs) or directly under the JDK’s lib directory (modern JDKs). This demonstrates how the JRE’s functionality is either included or integrated within the JDK.

  5. Verify java and javac Versions:

    • Execute the following commands to confirm that both the compiler and the runtime environment are accessible and correspond to your JDK installation: [,bash] ---- java -version javac -version ----

    • Expected Outcome: Both commands should output version information (e.g., openjdk version "17.0.8"). The output confirms that you have a full JDK installed, providing both compilation (javac) and execution (java) capabilities.

Validation Steps

  • You have successfully navigated to your JDK installation directory.

  • You have visually identified the javac and java executables within the bin folder.

  • You understand where the JRE’s core components (JVM and runtime libraries) reside within your specific JDK structure (either in a dedicated jre folder or integrated within the main lib directory).

  • You have successfully executed java -version and javac -version, confirming your JDK environment is correctly set up.

Common Errors and Troubleshooting

  • JAVA_HOME not set or incorrect PATH:

  • Symptom: Commands like java or javac are not found (e.g., "command not found" or "is not recognized as an internal or external command").

  • Troubleshooting: Ensure your JAVA_HOME environment variable points to the root of your JDK installation. Additionally, verify that $JAVA_HOME/bin (or %JAVA_HOME%\bin on Windows) is included in your system’s PATH environment variable.

  • javac not found, but java works:

  • Symptom: You can run Java programs, but you cannot compile them.

  • Troubleshooting: This often indicates that your PATH is pointing to a JRE’s bin directory, or you only have a JRE installed, not a full JDK. Ensure you have installed a JDK and that your PATH points to the JDK’s bin directory.

  • Multiple Java installations leading to version conflicts:

  • Symptom: java -version and javac -version report different versions, or an unexpected version.

  • Troubleshooting: Explicitly set JAVA_HOME to the desired JDK version’s root and ensure $JAVA_HOME/bin is at the beginning of your PATH variable to prioritize it. On Linux/macOS, tools like update-alternatives or sdkman can help manage multiple Java versions.

This hands-on activity directly demonstrates the practical structure of the JDK, illustrating how the JRE and the development tools are bundled together, reinforcing the conceptual understanding of their relationship.
